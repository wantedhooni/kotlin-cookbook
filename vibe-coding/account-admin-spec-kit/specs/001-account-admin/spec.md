# 기능 명세서: 계정 관리 Admin

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `001-account-admin` |
| 상태 | **초기 구현 소스 작성 완료 / 실행 검증 대기** |
| 작성일 | 2026-10-15 |
| 기준 기술 | Java 21, Kotlin 2.3.20, Spring Boot 4.1.1 |
| 대상 | 내부 운영 관리자 |

## 1. 문제 정의와 목표

내부 운영 관리자가 DB에 직접 접속하지 않고 웹 콘솔에서 계정을 생성·조회·검색하고 역할과 상태를 변경할 수 있어야 한다. 관리 행위는 감사 이벤트로 기록할 수 있도록 발행한다.

## 2. 범위

**포함**
- 계정 생성, 목록·상세 조회, 이메일·표시 이름 수정, 역할·상태 변경, 논리 삭제
- 키워드·역할·상태 기반 동적 검색 및 페이지 조회
- 환경변수 기반 개발용 관리자 인증(HTTP Basic)
- 간단한 관리자 웹 화면, Redis 계정 상세 캐시, Kafka 감사 이벤트

**제외**
- 최종 사용자의 로그인·비밀번호·비밀번호 재설정·회원가입
- SSO/OIDC 및 세부 권한 매트릭스(RBAC)
- 관리자 활동 이력 조회 화면, 삭제 계정 복구
- 결제, 프로필 파일 업로드, 계정 일괄 가져오기

## 3. 사용자 시나리오 및 인수 조건

### US1. 계정 목록 및 검색 (우선순위 P1)

- **전제(Given):** 개발용 관리자 인증에 성공했고 계정 데이터가 저장되어 있다.
- **행동(When):** 관리자가 키워드·역할·상태 필터와 페이지 번호를 지정한다.
- **결과(Then):** 조건에 맞는 계정과 총 건수·총 페이지 수를 일관된 정렬로 반환한다.

**인수 조건**
1. `keyword`는 `loginId`, `email`, `displayName`을 대상으로 대소문자를 구분하지 않고 검색한다.
2. 상태를 지정하지 않으면 `DELETED`를 제외한다. `status=DELETED`를 지정하면 삭제된 계정을 목록에서 조회할 수 있다.
3. 페이지는 0부터 시작한다. 기본 `page=0`, `size=20`, 허용 `size=1~100`이다.
4. 기본 정렬은 `createdAt DESC`, 동률이면 `id DESC`이다.
5. 존재하지 않거나 삭제된 계정의 상세 조회는 HTTP `404`를 반환한다.

### US2. 계정 생성 및 정보 수정 (우선순위 P1)

- **전제(Given):** 관리자가 인증되었다.
- **행동(When):** 유효한 로그인 ID·이메일·표시 이름을 제출한다.
- **결과(Then):** UUID를 가진 계정을 `ACTIVE` 상태로 생성한다. 역할의 기본값은 `USER`이다.

**인수 조건**
1. 로그인 ID는 영문·숫자·`.`·`_`·`-` 조합으로 3~50자이며 소문자로 저장한다.
2. 이메일은 소문자로 정규화해 저장하고, 표시 이름은 공백 제거 후 1~100자로 검증한다.
3. 정규화된 로그인 ID 또는 이메일이 중복되면 HTTP `409`를 반환한다. 동시 요청으로 DB UNIQUE 제약조건에 걸려도 동일하게 처리한다.
4. 요청 본문의 유효성 검증에 실패하면 오류 응답과 함께 HTTP `400`을 반환한다.
5. 수정 API는 이메일·표시 이름만 변경할 수 있으며 로그인 ID는 변경할 수 없다.

### US3. 역할·상태 변경 및 삭제 (우선순위 P1)

- **전제(Given):** 삭제되지 않은 기존 계정이 있다.
- **행동(When):** 관리자가 역할 또는 상태를 변경하거나 계정을 삭제한다.
- **결과(Then):** 변경 내용이 DB에 반영된다.

**인수 조건**
1. 역할 값은 `USER` 또는 `ADMIN`으로 제한한다.
2. 상태 변경 API에서 허용하는 상태는 `ACTIVE` 또는 `SUSPENDED`이다. `DELETED` 요청은 HTTP `400`을 반환한다.
3. `DELETE` 요청은 실제 행을 삭제하지 않고 `status=DELETED`로 바꾸며 HTTP `204`를 반환한다.
4. 삭제된 계정은 상세 조회하거나 다시 수정할 수 없다.
5. 실제 데이터 변경이 발생하면 해당 계정 UUID의 Redis 상세 캐시를 제거한다.

### US4. 관리자 인증·캐시·감사 이벤트 (우선순위 P1)

- **전제(Given):** 호출자가 유효한 초기 관리자 인증 정보를 제공하지 않았다.
- **행동(When):** `/api/admin/**` 엔드포인트를 호출한다.
- **결과(Then):** HTTP `401`로 요청을 거부한다.

**인수 조건**
1. 관리자 계정과 비밀번호는 환경변수로 주입하고 저장소에 실제 값을 커밋하지 않는다.
2. UUID 기준 상세 조회에 Redis 캐시를 사용할 수 있으며 TTL은 **5분**이다. 데이터 변경 시 해당 캐시를 제거한다.
3. DB 커밋 이후 `accounts.audit.v1` 토픽으로 `accountId`, `action`, `performedBy`, `occurredAt`을 포함한 이벤트를 보낸다. Kafka 메시지 키는 계정 UUID이다.
4. Kafka 발행 실패가 이미 커밋된 DB 트랜잭션을 되돌리지는 않는다. 이벤트는 최선 노력 방식이며 유실 위험을 문서화한다.

### US5. 웹 관리 화면 (우선순위 P2)

- **전제(Given):** 관리자가 내부 네트워크에서 브라우저로 접속한다.
- **행동(When):** 개발용 관리자 인증 후 화면을 사용한다.
- **결과(Then):** 검색·페이지 이동·계정 생성/수정·역할/상태 변경·삭제를 수행할 수 있다.

**인수 조건**
1. 로그인 정보를 `localStorage` 등 영구 브라우저 저장소에 저장하지 않는다.
2. 사용자가 입력한 문자열은 HTML로 해석하지 않고 텍스트로 렌더링한다.
3. 웹 UI 인증은 개발용 HTTP Basic의 제약을 그대로 따른다. 운영용 SSO/세션 인증은 범위 밖이다.

## 4. 비기능 요구사항

- 언어·프레임워크: Java 21, Kotlin 2.3.20, Spring Boot 4.1.1
- 저장·검색: JPA, OpenFeign Querydsl 7.1, PostgreSQL, Flyway
- 인프라: Redis, Kafka, Docker Compose
- 테스트: Kotest `BehaviorSpec`(BDD), MockK
- DB 스키마는 Flyway로만 변경하고 JPA `ddl-auto=validate`를 사용한다.
- 최대 페이지 크기를 제한하여 무제한 목록 조회를 방지한다.
- 현재 결과물은 **내부 개발용 스타터 프로젝트**이며 운영 보안 강화 및 인프라 통합 테스트는 후속 작업이다.
