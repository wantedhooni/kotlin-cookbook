# 계정 관리 Admin 프로젝트 헌장 (Constitution)

- **버전:** 1.0.0
- **제정일:** 2026-10-15
- **적용 대상:** Spring Boot 4 기반 계정 관리 Admin 및 GitHub Copilot Spec Kit 워크플로

## I. 명세 우선 개발

- 기능이나 외부 동작을 변경하기 전에 **요구사항·인수 조건(`spec.md`) → API 계약(`contracts/openapi.yaml`) → 구현 계획(`plan.md`) → 작업 목록(`tasks.md`)** 순서로 문서를 갱신한다.
- 기능 명세는 **무엇을·왜** 구현하는지, 구현 계획은 **어떻게** 구현하는지를 정의한다.
- 코드와 문서 사이에 불일치가 발생하면 이를 먼저 확인하고 수정한다. 문서를 실제 검증 결과처럼 꾸미지 않는다.

## II. 데이터 무결성

- PostgreSQL을 계정 데이터의 **최종 원본(Source of Truth)**으로 사용한다.
- 스키마 변경은 검토 가능한 Flyway 마이그레이션으로 관리하며, Hibernate 자동 스키마 변경을 사용하지 않는다.
- 로그인 ID와 이메일은 정규화(소문자) 후 저장하며, DB의 UNIQUE 제약조건으로 동시 요청 시 중복도 방지한다.
- 논리 삭제(Soft Delete)는 삭제 후에도 ID·이메일의 고유성 제약이 유지된다는 정책을 명확히 문서화한다.

## III. 기본 보안 원칙

- 계정 관리 API는 관리자 인증을 반드시 요구한다.
- 입력값을 검증하고, 인증 정보와 민감 데이터를 로그 또는 불필요한 API 응답에 포함하지 않는다.
- 관리 대상 계정의 `role=ADMIN`과 관리 콘솔의 관리자 인증 자격을 **서로 구분**한다.
- 환경변수로 주입하는 HTTP Basic 인증은 **개발용 초기 방식**이며, 운영용 보안 대책으로 간주하지 않는다.

## IV. 테스트는 인수 조건의 증거

- Kotest `BehaviorSpec`과 MockK를 이용해 정상·오류·경계 상황을 BDD 방식으로 테스트한다.
- 병합 전에 빌드와 테스트를 실행한다. 미실행 검증은 완료로 표시하지 않고 후속 작업으로 남긴다.
- DB·Redis·Kafka 통합 테스트가 빠져 있으면 미검증 사항으로 명시한다.

## V. 데이터 일관성 계약

- 계정 변경 시 해당 계정의 Redis 상세 캐시를 무효화한다.
- 감사 이벤트는 **DB 트랜잭션 커밋 이후** Kafka로 전송한다.
- 현재 전달 방식은 최선 노력(Best Effort)으로, Kafka 장애에 따른 이벤트 누락 가능성이 있다.
- DB와 Kafka 사이의 원자적 전달을 보장하지 않는다. 강화가 필요하면 Transactional Outbox를 도입한다.

## VI. 운영 가능성

- Docker Compose로 재현 가능한 개발 환경을 제공한다.
- 환경변수, 헬스 체크, 스모크 테스트, 문제 해결 절차를 문서화한다.
- 개발/운영 환경 간 인증·데이터 관리·이벤트 보장 수준의 차이를 명시한다.

## 헌장 변경 규칙

헌장 변경 시 버전을 갱신하고 해당 구현 계획에 변경 사유를 기록한다. 동작에 영향을 주는 내용은 명세·API 계약·테스트·README와 함께 업데이트한다.
